# Rigveda Sandhyavandana - Development Guide

## Project Overview
Rigveda Sandhyavandana is a Flutter application that provides a comprehensive, interactive guide for the daily Rigveda Sandhyavandana ritual. It serves as the baseline architecture from which sibling apps (like Nitya Puja) are modeled.

## CI/CD Pipeline
The CI/CD pipeline is fully automated using GitHub Actions.

### Workflows
1. **CI (`rig_sandhya_ci.yml`)**: Triggered on every push and pull request to the `flutter_rig_sandhya/` directory.
   - Runs Flutter format checks.
   - Runs `flutter analyze` for strict linting.
   - Executes Widget tests (`flutter test`).
   - Executes Integration tests on a headless Android emulator.

2. **CD (`rig_sandhya_cd.yml`)**: Triggered manually via `workflow_dispatch` or by pushing a tag matching `rigsandhya-v*`.
   - Automatically bumps the version in `pubspec.yaml`.
   - Commits the version bump and creates a GitHub release tag.
   - Decodes the Base64 Keystore from GitHub Secrets and injects it into `key.properties`.
   - Builds a signed Android App Bundle (`.aab`).
   - Uploads the `.aab` to the Google Play Console Internal Track using `r0adkll/upload-google-play@v1` and looks for release notes in the `whatsnew/` directory.

### Secrets Required
The CD pipeline relies on the following GitHub Repository Secrets:
- `KEYSTORE_JKS`: Base64 encoded string of `mankalmadhu_keystore.jks`.
- `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`: Passwords for the keystore.
- `PLAY_STORE_SERVICE_ACCOUNT_JSON`: The service account JSON to authenticate with Google Play Console.

### Signing Configuration
Rig Sandhya uses `mankalmadhu_keystore.jks` as its Upload Key for the Google Play Store (matching SHA-1 `F7:96...`). The `android/app/build.gradle` (or `build.gradle.kts`) is explicitly configured to read the `key.properties` file generated by GitHub Actions to sign the `release` build.

## Testing & Quality
### Integration Tests
Integration tests are located in `integration_test/app_test.dart`.
**Critical Note**: Because the app relies on dynamic font fetching, `GoogleFonts.config.allowRuntimeFetching = true;` is required in the test setup. Furthermore, local storage (like SharedPreferences) is mocked during tests to ensure isolated and repeatable test states.

### Code Quality
- All code must pass `flutter analyze` with 0 issues.
- Formatting must perfectly match `flutter format .`.

## Local Development
To build the release version locally, you must have the `key.properties` file in your `android/` directory:
```properties
storePassword=<password>
keyPassword=<password>
keyAlias=mankalmadhukey
storeFile=mankalmadhu_keystore.jks
```
Place `mankalmadhu_keystore.jks` in the `android/app/` directory.

Run:
`flutter run -d macos` (for local desktop testing)
`flutter build appbundle --release` (for Android Play Store builds)
